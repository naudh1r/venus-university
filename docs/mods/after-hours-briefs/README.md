# After Hours briefs: standing rules

Read this before every brief. It holds what every round must keep, including what was corrected after
the earlier rounds.

## Branches
- Everything lives in `naudh1r/venus-university` (remote `origin` for Codex). Push only there, never to
  `venus-extracurriculars/build`. Open no pull request.
- `hooks/after-hours`: core and kit changes only, on the org's `main`. Nothing on it names After Hours.
- `mod/after-hours`: the mod, on top of `hooks/after-hours`.
- **Start every round by fetching both branches fresh from the fork and resetting your local copies to
  them** (`git fetch origin && git checkout -B <branch> origin/<branch>`). Commits on the fork get
  re-signed and rewritten; an old local copy must never be pushed back.
- A mod round starts by merging the **current** `origin/hooks/after-hours` into `mod/after-hours`.

## Commits
- Author `Naudh1r <102735014+naudh1r@users.noreply.github.com>`, signed, no co-author lines.
- One commit per brief, message in the repo's style: an imperative summary line, a short body if needed.

## Fixes made after earlier rounds (do not repeat them)
1. **Never commit `packages/modkit/dist/`.** It is generated by `npm run report` and gitignored; the org's
   `main` does not track it. Commit `packages/modkit/api/*.api.md` only. (Round A committed 12,000 lines
   of it; removed.)
2. **Merge the current hooks branch, not an old one.** Round 0.1.0 merged a stale hooks commit and brought
   the removed `dist/` back; the branch was rebuilt.
3. **Shared code never imports renderer code.** `src/shared/**`, the mod entries in
   `src/shared/modEntries/` included, are read by the main process too. Text the entry needs lives in
   `src/shared/` (`src/shared/afterHoursText.ts`), and the renderer imports it from there.
4. **Keep the kit's lists in order.** Export lists in `packages/modkit/src/host/*.ts` and
   `packages/modkit/src/renderer/index.ts` are alphabetical; put a new name in its place.
5. **A test file says what it defends:** wrap its cases in a `describe` named for that, as the repo's
   tests do.
6. **Never hand the model a player-facing label.** The AI is not told about a "Busy status": a word on the
   player's screen became the topic of her texts. Prompt lines describe the situation in the fiction
   ("the reader is staying in for now"), say how she behaves, and say when it is background she does not
   talk about.
7. **Change nothing the brief does not ask for.** Round B also changed how `src/main/paths.ts` checks
   ComfyUI's output paths; it was unrelated and reverted. If something outside the brief looks wrong or
   a test fails for an unrelated reason, report it instead of fixing it.

## Always
- Read `CLAUDE.md`, `DESIGN_GUIDE.md`, `MODDING.md`, and `UI_STYLE_GUIDE.md` for anything on screen.
- Never edit `DESIGN_GUIDE.md`, `UI_STYLE_GUIDE.md`, `README.md` or `TESTING_PLAN.md`.
- A mod is hooks-only: its files import only `@vx/modkit/*`, React, `motion/react` and its own files, and
  `test/kit/boundaryAllowlist.json` gets zero new lines. If something cannot be done that way, stop and
  say what is missing.
- Comments say what the code below does; never point at a guide; never history.
- Tests only for the pure rules a save or a decision is computed from; none for wording, labels or looks.
- `npm run typecheck` and `npm test` pass. In this environment 11 test files that write zips with 7-Zip
  may fail the same way they fail on the org's `main`; nothing else may fail.
- For a kit change: `cd packages/modkit && npm install && npm run report`, then `npm run report:check`.
